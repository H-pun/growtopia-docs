# Character Rendering

The client builds the avatar every frame from small 32 × 32 sprites. It has no pre-baked character image. Body parts are blitted around one avatar origin, and clothing is layered over them in a fixed order. Items that need more than one sprite go through one of the [special render paths](/docs/character-rendering/special-outfits).

<Callout type="info" title="Source">
Everything on this page comes from the macOS x86_64 client (decompiled) and the textures shipped in the `.dmg`. Lines marked **guess** were fitted against reference screenshots and are not traced in code yet.
</Callout>

---

## 1. Coordinate Origin

Every part is positioned relative to the avatar origin `(X, Y)`:

- `X`: horizontal center of the 32 px avatar cell.
- `Y`: bottom row of the cell (the ground line).

Facing left mirrors the whole avatar around `X`. Arm rotations are negated as part of the mirror.

```ts
// cell top-left from origin
const cellX = X - 16, cellY = Y - 32;
```

## 2. Body Parts

| Part | Texture | How it is drawn |
|---|---|---|
| Body | `player_body_only` | One 32 × 32 frame. The column depends on what is worn (see below). |
| Legs | `player_extraleg` | A 1 px tall strip, stretched vertically to `foot + 2` px. |
| Head | `player_head` | 32 × 32 at the cell. |
| Eyes / face | `player_eyes`, `player_face` | Blink frames or expression frame, same cell as the head. |
| Feet | `player_feet` | One frame per foot, moved down by `foot` px. |
| Arms | `player_arm` | 8 × 16 sprite, aligned upper-center and rotated around the shoulder. |
| Sleeve | `player_sleeve` | 32 × 32 frame on top of each arm. Uses the arm's anchor and rotation. |
| Sit pose | `player_sit` | Frame `(1, 0)`, aligned down-center at `(X, Y + 9)`. Replaces the legs and feet. |

All of these except the eyes and face are tinted with the skin color (see [Tinting](#4-tinting)).

### Body column

The torso sprite contains bare skin and an undershirt/shorts version side by side. The column is picked from the shirt and pants slots:

```ts
const col = (shirt ? 1 : 0) + (pants ? 2 : 0);
// 0 undershirt + shorts, 1 skin torso + shorts, 2 undershirt + skin hips, 3 all skin
```

Clothing is drawn on top afterwards. A shirt or pants sprite with holes therefore shows skin rather than the white undershirt.

### Legs

```ts
// leg frame 0 at x+8 follows foot2, frame 1 at x+16 follows foot1
drawImage(extraleg, 0, 0, 8, 1, cellX + 8,  cellY + 28, 8, foot2 + 2);
drawImage(extraleg, 8, 0, 8, 1, cellX + 16, cellY + 28, 8, foot1 + 2);
```

<Callout type="warn" title="Guess">
The strip's start row (`cellY + 28`) was pixel-fitted. The anchor mode in code is not decoded yet.
</Callout>

### Arms

| Arm | Anchor | Rotation |
|---|---|---|
| Back arm | `(X + 8, Y - 14)` | `arm1` |
| Front arm | `(X - 7, Y - 14)` | `arm2` |

The arm is aligned upper-center with rotation point `(0, 1)`. The planner shifts the blit `-3` px in x to match pixel-for-pixel. That value is a **guess**, because the pivot math is not fully decoded.

## 3. Draw Order

These steps are traced in code, from back to front:

1. Back arm (+ sleeve)
2. Body, then legs
3. Head, then eyes/face
4. Sit sprite (only when sitting)
5. Feet or shoes
6. Pants
7. Shirt
8. Front arm (+ sleeve)

The other slots hook in around these steps: back item, back hair/hat, chest, face item, hair, hat, hand item. A data-driven item can also add a pass behind or in front of the whole avatar. The hook names and where each one fires are covered on the [ItemRenderers XML](/docs/character-rendering/item-renderers) page.

<Callout type="warn" title="Order of the remaining slots">
The exact position of the back item, face item, hair, hat and hand item relative to the steps above has not been fully traced yet.
</Callout>

## 4. Tinting

The client tints with a plain multiply that keeps the sprite's alpha:

```ts
function tint(img, hex) {
  const c = new OffscreenCanvas(img.width, img.height), g = c.getContext('2d');
  g.drawImage(img, 0, 0);
  g.globalCompositeOperation = 'multiply'; g.fillStyle = hex; g.fillRect(0, 0, c.width, c.height);
  g.globalCompositeOperation = 'destination-in'; g.drawImage(img, 0, 0);
  return c;
}
```

### Seed-colored clothing

Clothing whose `visual_type` is one of `20, 22, 27, 38, 39` is drawn in two layers:

- Frame `x` is tinted with the **seed color** of the item's seed (`item_id + 1`).
- Frame `x + 1` is tinted with that seed's **overlay color** and drawn on top.

Muscle Shirt, Super Shirt, High Heels and Crystal Wings all use this path. The colors come from `bg_col` / `fg_col` of the seed record in `items.dat` (see [Seed Rendering](/docs/items-dat/seed-rendering)).

```ts
const TINTED = new Set([20, 22, 27, 38, 39]);
if (TINTED.has(item.visual_type)) {
  const seed = items[item.id + 1];
  blit(tint(tex, seed.bg_col), item.tex_x,     item.tex_y);
  blit(tint(tex, seed.fg_col), item.tex_x + 1, item.tex_y);
}
```

### Two-frame blink

Clothing with `visual_type` 4 or 7 switches between frame `x` and `x + 1` every 200 ms:

```ts
const frame = item.tex_x + (Math.floor(nowMs / 200) & 1);
```

### Sleeves

A shirt adds sleeve sprites to both arms. The sleeve frame index is stored in the shirt's item record. A value of `1` means "no sleeve".

- The sleeve frame is tinted with the shirt seed's **seed color**.
- Frames `0, 2, 4, 6, 10` are two-layer sleeves: frame `n + 1` is drawn on top, tinted with the **overlay color**.

```ts
const TWO_LAYER = 0x455; // bits 0,2,4,6,10
const layers = (TWO_LAYER >> f) & 1 ? [[f, seedColor], [f + 1, overlayColor]] : [[f, seedColor]];
```

<Callout type="warn" title="Not covered">
Dyed and rainbow clothing (`visual_type` 25) goes through a color-cycle function that is not decoded yet.
</Callout>

## 5. Clothing Slots

The `clothing_type` field in `items.dat` picks the slot:

| `clothing_type` | Slot | Typical sheet |
|---|---|---|
| 0 | Hat | `player_hat*`, `player_cosmetics*` |
| 1 | Shirt | `player_shirt*` |
| 2 | Pants | `player_pants*` |
| 3 | Shoes | `player_feet*` |
| 4 | Face | `player_faceitem*` |
| 5 | Hand | `player_handitem*` |
| 6 | Back | `player_back*` |
| 7 | Hair | `player_hair*` |
| 8 | Chest | `player_chestitem*` |
| 9 | Ancestral | — |

Newer items from any slot live on the `player_cosmetics*` sheets.

<Callout type="warn" title="Numbering">
The renderer checks the shirt as slot `1` and the hat as slot `0`, so the numbering is 0-based. The Ancestral row has not been checked against code.
</Callout>
