# Animation Engine

Avatar movement uses no sine curves. Each limb has a value and a target. Every frame, the value moves toward its target by a fixed amount per second. The state machine decides when the targets change. This is what makes the Growtopia walk look "snappy" instead of smooth.

---

## 1. Limb State

| Field | Meaning | Range |
|---|---|---|
| `foot1`, `foot2` | Foot vertical offset in px (positive = down) | clamped `[-2, 1]` |
| `tgt1`, `tgt2` | Where each foot is heading | |
| `arm1`, `arm2` | Back / front arm angle in degrees | `[0, 360)` |
| `phase`, `lead` | Which foot is currently stepping | bool |

Two helpers do all the motion:

```ts
// linear move toward target, stops exactly on it
const approach = (v, t, step) => v <= t ? Math.min(v + step, t) : Math.max(v - step, t);

// angle move toward target, wraps through 0/360 when that is shorter
function approachDeg(v, t, step) {
  const d = Math.abs(t - v), s = Math.min(step, d);
  if (d < 180) return t <= v ? v - s : v + s;
  const r = v <= t ? v - s : v + s;
  return ((r % 360) + 360) % 360;
}
```

## 2. States

The avatar state is one of `idle`, `walk`, or `air`. `air` applies whenever the player is off the ground.

### Idle

```ts
foot1 = approach(foot1, tgt1, 20 * dt);
foot2 = approach(foot2, tgt2, 20 * dt);
tgt1 = tgt2 = 0;
const fast = Math.abs(arm1) > 20 || Math.abs(arm2) > 20;
arm1 = approachDeg(arm1, 0, (fast ? 900 : 100) * dt);
arm2 = approachDeg(arm2, 0, (fast ? 900 : 100) * dt);
```

The body itself does not bob in idle. Only the limbs settle back to rest.

When horizontal velocity becomes non-zero, the state switches to walk. Entering walk flips the leading foot. The leading foot's target becomes `-2` (lifted) and the other foot's target becomes `0`.

### Walk

```ts
const step = Math.abs(velX) / maxSpeed * 20 * dt;
foot1 = approach(foot1, tgt1, step);
foot2 = approach(foot2, tgt2, step);

if (!phase && foot1 <= tgt1)     { phase = true;  foot1 = tgt1; tgt1 = 1; tgt2 = -2; }
else if (phase && foot2 <= tgt2) { phase = false; foot2 = tgt2; tgt2 = 1; tgt1 = -2; }

// arms follow the feet
arm1 = approachDeg(arm1, wrap360((foot1 + 1) * 20), 900 * dt);
arm2 = approachDeg(arm2, wrap360((foot2 + 1) * 20), 900 * dt);
```

The feet alternate. One foot is lifted to `-2` while the other is pushed to `1`. The arms have no motion of their own: each arm angle is derived from its foot, so they swing in step with the legs.

When velocity drops back to zero, the state returns to idle.

<Callout type="info" title="Held weapons">
Some held items change the walk: `arm1` targets `(foot1 + 1) * 10 - 45` instead, which keeps the arm raised.
</Callout>

### Air (jump / fall / hover)

```ts
foot1 = approach(foot1, tgt1, 30 * dt);
foot2 = approach(foot2, tgt2, 30 * dt);
const [t, angle, speed] = rising ? [1, 200, 900] : [-2, 330, 200];
tgt1 = tgt2 = t;
arm1 = approachDeg(arm1, angle, speed * dt);
arm2 = approachDeg(arm2, angle, speed * dt);
```

- **Rising** (`velY < 0`): feet go down, arms swing fast to 200° (raised).
- **Falling or hovering** (`velY >= 0`): feet go up, arms ease slowly to 330°.

Once the state is updated, both feet are clamped to `[-2, 1]`.

## 3. Blink

Eyes use 3 frames: open, half, closed. The planner shows the closed sequence for about 200 ms every 2.5–5.5 s.

## 4. Using It in a Planner

A planner has no physics, so the inputs are faked:

| Planner action | Input |
|---|---|
| Idle | `velX = 0`, on ground |
| Walk | `velX = maxSpeed`, on ground |
| Jump | air, rising |
| Fly / hover | air, `velY = 0` (falling branch) |

```ts
function step(dt, action) {
  if (action === 'JUMP' || action === 'FLY') air(dt, action === 'JUMP');
  else if (action === 'WALK') { if (!walking) startWalk(); walk(dt, 1); }
  else { walking = false; idle(dt); }
  foot1 = clamp(foot1, -2, 1); foot2 = clamp(foot2, -2, 1);
}
```

The resulting feet and arm values go straight into the draw code described in [Character Rendering](/docs/character-rendering).
