# Special Outfits

A normal clothing item is one 32 × 32 frame drawn at its slot's position. About 600 items are drawn some other way. The client has **four separate mechanisms** for this, and an item can use more than one of them.

| # | Mechanism | Where the data lives | Items |
|---|---|---|---|
| 1 | Visual-effect field | `visual_type` in `items.dat` | hundreds (most common values listed below) |
| 2 | ItemRenderers XML | `GameData/ItemRenderers/*.xml` | 618 files |
| 3 | Hardcoded item-ID checks | compiled into the renderer | 308 item IDs |
| 4 | Full custom renderer | compiled into the renderer | Legendbot-009 |

A planner that only blits the item's frame renders all of these wrong.

---

## 1. Visual-Effect Field (`visual_type`)

The renderer reads the item's `visual_type` byte and changes how the frame is drawn. All values below are confirmed in code:

| Value | Effect | Example |
|---|---|---|
| `4`, `7` | Blink between frame `x` and `x + 1` every 200 ms | — |
| `8` (shirt) | **Hide both arms** (back and front arm skipped) | Giant Snowball Suit, Arcane Armor, Kimonos, Cultist Robe |
| `20, 22, 27, 38, 39` | Two-layer seed tint (frame `x` seed color, `x + 1` overlay color) | Muscle Shirt, High Heels, Crystal Wings |
| `25` | Color-cycling (rainbow) tint | — |

The tint and blink rules are described in [Character Rendering → Tinting](/docs/character-rendering#4-tinting).

### Armless shirts (`visual_type = 8`)

When the equipped shirt has `visual_type == 8`, the arm sprites and their sleeves are not drawn. Bulky costumes rely on this: their sprite already includes the arms, or the body is a ball. 22 shirts use it:

> Cultist Robe, Growch Cultist Robe, Architect's Robes, Pink/Blue/Orange Kimono, Winter Freezer Robe, Ultra Winter Freezer Robe, Emperor's Jacket, Drednok's Robe, Kuchisake Kimono, Pocong Clothes, Emperor's New Robes, Jellyfish Onesie, Arcane Armor, Royal Arcane Armor, Body of Ahool, Candlewick's Dress, Aurora Robe, Hanfu, REALLY Really Big Jeans, Giant Snowball Suit

```ts
const noArms = equipped.shirt?.visual_type === 8 || equipped.hand?.id === 5480; // 5480 = Rayman's Fist
if (!noArms) { drawBackArm(); /* ... */ drawFrontArm(); }
```

<Callout type="info" title="Giant Snowball Suit">
This one has no XML and no ID check. Its whole special look comes from `visual_type = 8`: the arms disappear and only the ball sprite is left.
</Callout>

<Callout type="warn" title="Other values">
Many other values appear on clothing: `4` (247 items, mostly back), `6` (378, mostly hand), `23` (123, face), `47` (74, hair), `19`, `20`, and others. Only the rows in the table above have been traced in code.
</Callout>

### Not a hide mask

The item record also has a byte at the position the docs call `aura_slots[0]`. The renderer checks it as a per-part hide mask:

| Bit | Hides |
|---|---|
| `0x04` | Standard shirt blit |
| `0x08` | Front arm |
| `0x10` | Back arm |

In the current `items.dat` (v27), this byte is `0` for every one of the 16,434 items. In practice it is never used, so arm hiding always comes from `visual_type`.

## 2. ItemRenderers XML

This is the biggest group. An XML file describes extra sprites, offsets and animations, and hooks them into named render passes. The full format is covered in [ItemRenderers XML](/docs/character-rendering/item-renderers).

Example, Arcane Armor:

- `RenderShirt` replaces the shirt blit with the armor plate. On top of it sits a glow frame that pulses over 5 s.
- `RenderBehind` / `RenderInFront` add two floating claws on magic circles at `(±31.6, −29.15)` from the avatar.
- Together with `visual_type = 8`, the real arms are hidden, so the claws act as the hands.

## 3. Hardcoded Item-ID Checks

The draw functions compare the worn item ID against constants. Scanning the avatar draw code found **308 different item IDs** checked this way. Most checks are small tweaks, such as shifting a sprite by a few pixels, picking another frame, or skipping a body part.

| Slot | IDs | Typical items |
|---|---|---|
| Shoes | 129 | Vehicles and mounts: Pleiadian Star Ship, Toboggan, Floating Leaf, Magic Carpet, Riding RV |
| Back | 54 | Vampire Cape, Phoenix Wings, Golden Aura |
| Hand | 53 | Guitars, Basketball, Party Blaster |
| Chest | 18 | |
| Hat | 15 | |
| Face | 15 | Vampire Fangs, Sabertooth Growtopian |
| Shirt | 10 | Galaxy Skin (14 checks) |
| Hair | 7 | Afro, Cultist Hood |
| Pants | 7 | Mermaid Tail (12 checks), Raptor Legs (11) |

The items with the most checks are almost all rides: Zamgrowni, Sturdy Crackfire Fighter, Wacky Rocket Sled, Pineapple Plough, Alien Recon Wagon, Demon Night Stallion. Rides move the whole avatar, so many draw steps have their own branch.

Examples that have been traced:

```ts
// pants: these shoes hide the pants entirely
if ([0x2f12, 0x3340, 0x29aa, 0x2ba0].includes(shoes.id) || (shoes.id >= 0x22c2 && shoes.id < 0x22c9)) skipPants();

// pants: some shoes push the pants 1 px left/right and 2 px down
if (shoesShiftPants(shoes.id)) { x -= facingLeft ? -1 : 1; y += 2; }

// feet: frame + 1 when foot < -0.5, except for a few shoes
if (foot < -0.5 && ![0x62e, 0x950, 0x95a, 0x126a, 0x2aee].includes(shoes.id)) frame++;
```

<Callout type="warn" title="Not ported">
The table is a complete list of *which* items are special-cased. What each branch actually does has only been worked out for the examples above.
</Callout>

## 4. Full Custom Renderer: Legendbot-009

Legendbot-009 (`1780`) is the only item with a complete renderer of its own. When it is the equipped shirt, the normal body path is replaced: the client assembles a mech out of parts.

- Textures: `lb9_parts` (64 × 64 cells) and `lb9_back` (41 × 47). Both are loaded once with the other avatar textures.
- Pieces, back to front: back arm, body, legs, head, hat, front arm.
- Each piece has its own offset from the avatar, for example `(X + 21, ...)`, `(..., Y − 29)`, `(X + 20, Y − 32)`, `(..., Y − 15)`.

<Callout type="warn" title="Not ported">
The exact frame for each piece has not been mapped yet. A planner that blits the 32 × 32 shirt frame shows only a small chest piece.
</Callout>

## 5. Checking an Item

To see which mechanisms an item uses:

1. Read `visual_type` from `items.dat`. A value of `8` on a shirt means armless. Tint and blink values change the frame.
2. Look for `GameData/ItemRenderers/<Name>.xml`. The file name is usually the item name without spaces, and the item record points to it.
3. Check the item's ID against the hardcoded list.
4. If the item is `1780`, it uses the Legendbot path.

Items that hit none of these are drawn as a single 32 × 32 frame.
